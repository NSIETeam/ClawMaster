# Agent Note: 业务任务使用可信调用身份

Status: implemented

[English](2026-09-16-watchdog-task-identity.md) | 中文

## Problem

代理活动无法代表业务验收，桌面 Host 令牌也不标识组织成员。任务验收与记录变更需要独立的业务状态和当前授权。

## Decision

WatchDog 前端拥有持久任务、按修订提交的命令、保留的提交/验收历史及 HTTP/工具消费者。DSH Session 继续负责执行。导入已有 Session 会创建带明确来源的草稿；空闲或停止的 Session 不代表完成。代理可以提交证据，验收、取消和重新打开由仅限人工的迁移执行。组织中的提交者不能验收自己的结果。

同一个 GovernanceAccess 实例通过可信权威服务解析调用者身份，每次操作都检查角色和资源，包括异步审批之后。权威服务在服务端绑定代理 Session；委派权限取当前发起者与被委派者权限的交集。记录变更、任务写入和恢复消费绑定命令、资源、代次、修订和摘要的一次性批准。DSH 工具批准不能替代企业批准。人工任务验收直接要求验收角色。已提交任务的相同重试检查当前权限，不再索取另一份批准。完整快照要求组织范围的记录与审计读取权限；企业写入仅返回回执元数据。数据库的组织绑定在业务恢复之后保留。本地操作者仍明确属于本地，已有数据不会自动上传或改变组织。[责任历史](2026-09-16-enterprise-responsibility-history.zh.md) 在被恢复的业务历史之外记录可信操作者与策略事实。

任务响应预算约束最终 HTTP JSON 和 DSH 值/内容信封，计入 UTF-8 与 JSON 转义。仅限制行数不能约束包含长验收项或证据的任务。修改在写入前检查完整的新任务能够放入单条记录的分页；被拒修改保留原有修订和历史。列表和历史读取逐行迭代，达到配置的字节或行数上限就返回续读位置，不会静默丢弃数据。历史续读位置是不变的修订号。纯线协议 schema 和任务标记位于与浏览器共享、不依赖 Node 的模块。

## Alternatives considered

**从 Session 活动推导业务状态。** 停止的 Session 可能表示待验收、失败或取消；这些结果需要明确的任务命令。

**接受请求 JSON 或桌面访问令牌提供的成员编号。** 两者都不能证明组织身份。企业配置需要独立认证的提供者，缺失或不可用时拒绝执行。

**仅在页面渲染时检查权限。** 已打开的页面或排队工具可能保留已撤销权限。两种传输入口都在执行时检查当前成员权限。

## Consequences

本地任务和审计 API 不需要身份提供者。企业消费者提供集成接口，不是内置登录系统，也不是已部署多人服务的证明。附件服务、本地到企业迁移和真实桌面业务流程仍需集成。测试覆盖真实 DSH 工具 schema/审批/输出链路、跨组织拒绝、审批等待期间撤权、委派、数据库组织绑定、过期命令和重交证据保留。关闭产品 Issue 前仍需录制会话快照与桌面界面验收。

# Agent Note：企业资源授权键类型化

Status: implemented

[English](2026-09-17-typed-resource-grants.md) | 中文

## 问题

企业成员授权在记录、任务、调度和工作空间分配中使用裸资源 ID。同一授权因此可能命中同一个 ID 表示的不同资源类型。提交订单还会修改其关联库存行，所以仅有订单本身的权限并不足够。

## 决定

Host 使用 `governanceResource(kind, id)` 创建资源键。记录资源族使用 `record/contact`、`record/inventory`、`record/order` 和 `record/audit`；其他资源族使用 `task`、`schedule` 和 `workspace`。ID 在加入资源键前进行 URI 编码。`governanceResourceCollection(kind)` 返回资源族通配符，`*` 仍表示组织范围的授权。

共享 `GovernanceAccess` 求值器接受精确键、匹配的 `<资源族>/*` 授权或 `*`。即使权威服务返回了匹配的裸 ID 授权，它也会拒绝未类型化的资源字符串。每个 HTTP 路由、DSH 工具、任务 Host、调度 Host/运行时及托管工作空间分配器都为资源传入相同的类型化键。查询整个资源族需要该族通配符或组织范围的授权。按 ID 查询时会检查该资源的精确键。

提交订单前，系统会检查订单以及每个关联库存项目的写权限，之后才审批或提交。审批仍绑定订单 ID、命令、恢复代次、修订和摘要。

裸资源授权不会自动转换。因为它们无法区分资源族，系统会拒绝它们；企业权威服务必须在部署此版本前更新授权映射。Local 模式继续使用设备所有者授权，不读取企业资源授权。

## 考虑过的替代方案

**保留裸 ID。** 它们无法区分复用同一 ID 的联系人、库存项目、任务和调度。

**只要求组织范围的 `*`。** 这能消除歧义，但会失去对单个记录与资源族进行最小授权的能力。

## 后果

类型化授权保留单资源和资源族访问，同时防止相同 ID 跨资源族复用。现有权威服务集成必须显式迁移授权；应用不会推断或扩大授权。产品没有内置身份提供者、附件服务或多组织桌面部署，因此这些路径仍需按部署集成并验收。

治理访问测试覆盖精确键和跨资源类型的资源族通配符拒绝。真实注册 HTTP 与工具查询测试在联系人和库存中使用相同 ID，并拒绝未经授权的资源集合。回执测试覆盖 HTTP 和 DSH ToolRuntime 下的类型化授权与审批。双组织 fixture 拒绝外部主体访问 HTTP 记录、写入、备份导出和 DSH 工具。

# Agent Note: 企业子串搜索由三元索引收窄候选

Status: implemented

[English](2026-09-17-enterprise-trigram-search.md) | 中文

## Problem

企业搜索会对每个可搜索字段执行子串匹配，包括较大的审计变更前后 JSON。即使查询只命中少数记录，处理量仍会随全部行数增长。

## Decision

Schema 6 在可搜索的 SQLite 列上创建外部内容 FTS5 三元索引。插入、更新和删除触发器会与源行在同一事务中维护索引。迁移会在提交 schema 版本前，根据现存数据重建索引；业务记录不会被修改，备份也不会导出派生索引数据。

对于至少包含三个可打印 ASCII 字符的查询，FTS 会先收窄候选行 ID。现有的忽略 Unicode 大小写子串匹配仍是最终判定。较短、非 ASCII、含 NUL 或无法以有效 UTF-8 表示的查询继续使用原扫描路径，以保留子串行为和 SQL 字面查询语义。

## Alternatives considered

**使用文本 B-tree 索引。** B-tree 无法收窄带前导通配符的 contains 查询，也无法在不改变查询约定的前提下索引任意审计 JSON。

**将子串搜索改为词项搜索。** 分词会改变命中结果，尤其影响标点、标识符和不以空格分词的语言。

**继续扫描每一行。** 这能保留现有行为，且无需迁移或增加写入成本，但搜索耗时仍会随整个集合增长。

## Consequences

FTS 索引保存派生词项，会增加磁盘占用和写入开销。SQLite 负责同步，源列仍是权威数据。迁移在事务中执行；如果 FTS5 不可用或建索引失败，事务回滚且不会推进 schema 版本。选择性强的搜索会先筛选候选项；命中率高或关键词较短时仍可能扫描许多行。

企业搜索测试会将所有分页结果与字面子串语义比较，并覆盖 Unicode、标点、订单物料 ID、审计 JSON、更新、删除、恢复和 schema 5 迁移。仓库本地容量诊断在相同合成数据集上记录前后搜索延迟；这些耗时仅供诊断，不构成发布性能保证。

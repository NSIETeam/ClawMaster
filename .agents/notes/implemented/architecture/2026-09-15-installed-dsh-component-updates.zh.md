# Agent Note: 已安装 DSH profile 中的组件更新

Status: implemented

[English](2026-09-15-installed-dsh-component-updates.md) | 中文

## 问题

已安装桌面的原生更新端点编译在二进制中。修改服务器 manifest（元数据清单）或 DSH profile 无法修改该端点。每次独立组件交付都要求完整替换桌面，也会把组件交付与原生打包绑在一起。运行中的更新器必须区分首次添加自身与替换自身，并在协调 profile 重载时保留用户编辑。

## 决策

[DSH 更新插件](../../../../frontends/updates/README.zh.md)挂载到现有 web profile，复用 DSH 命令、工具及一次性用户批准。首次安装工具仅运行有限操作，读取明确选择的 DSH 主目录和运行时根目录。默认操作展示计划，不修改文件；明确确认绑定计划的摘要和 profile 修订号，随后安装已认证的组件字节，仅添加更新器的首个 profile 配置行。已有更新器配置行或已声明的更新器依赖会拒绝该首次挂载。工具不是应用启动器，该包也未声明 `dsh.bundle.patch`。

[更新接入包](../../../../frontends/updates/kit/README.zh.md)携带已签名的本地组件文件，支持离线首次挂载。检查通过 `dsh-launch.json` 及桌面记录定位安装，再检查实际运行时包。记录负责定位文件，不能证明兼容。确认安装绑定所选摘要及 profile 修订号，并备份三个相关 profile 配置文件，不读取独立凭据文件或收集业务数据。备份文件使用 `0600`；配置可能包含内嵌凭据，因此须私有保存。位置缺失或运行时不兼容会返回明确结果，不强行激活。

组件目录使用独立于原生 Tauri 密钥的固定 Ed25519 公钥。签名认证目录原始字节，包括每份不可变产物的版本、摘要、大小、DSH 兼容性及激活方式。组件产物自包含；安装会校验归档路径、依赖及文件哈希，不运行包管理器生命周期脚本。没有组件签名密钥，分发服务器不能修改这些已签名事实。

只读发现与更新准备彼此独立。一次批准将更新操作绑定到已认证候选元数据、运行中 Host 及已查看的 profile 修订号。热激活仅编辑被监视 web profile patch 中更新器所属的配置行，并返回等待 Loader 的状态及回滚令牌。由 Loader 而非成功写文件来确定新插件已生效。维护者确认后的回滚要求后继修订号仍为当前值，保留期间发生的用户编辑；回滚 API 不通过命令或工具开放。

更新器自身及其他须重启组件只会暂存，不替换被监视的配置行。更新器首次挂载是唯一的运行中首次安装例外，因为它不替换任何已加载的更新器。仅重启应用不会应用暂存变更；替换须另行在 Host 停止后安装。DSH 核心及原生应用文件不属于热激活范围。原生产物准备保留 Tauri Minisign 验签，并返回需要原生安装的状态，不启动安装器。

更新器 `0.1.2` 使用原生 v2 端点，接受四个必需安装器目标及可选的旧版 Intel Mac 条目。缺少 Intel 元数据时，在审批或文件准备前将该机器的原生通道标为不可用，不影响组件发现。旧端点服务于严格要求五个目标的旧解析器。已发布的更新器版本及接入包 `0.1.0` 保持不可变，须另行升级；接入包保留旧端点。修改服务器元数据或重启都不会替换它们的解析器。原生文件 URL 仅限于配置清单所在目录的精确版本子目录。测试覆盖两种可接受的目标集合、v2 下载、跨通道拒绝、逐个缺失必需目标、未知目标，以及拒绝时不审批、不下载、不写入。无密钥 ACP 会话快照通过生产更新工具读取四目标元数据，将缺少 Intel 的错误持久化，并验证最终工作区为空且没有审批事件。

[原生正式版更新决策](2026-09-13-desktop-stable-confirmed-updates.zh.md)继续负责原生版本选择、检查调度及安装确认。[自托管发布决策](2026-09-15-desktop-self-hosted-update-channel.zh.md)继续负责原生发布文件的镜像及原子发布。此插件新增独立的组件消费方，不改变这两项决策，也不改变已安装 `0.2.1` 二进制的端点。包 README 负责用户操作及限制；[服务器参考](../../../../apps/desktop-tauri/server-updates/README.zh.md)负责发布流程。

## 考虑过的替代方案

**每次引入组件都替换桌面。** 原生应用及核心变更仍需原生打包。独立组件可以复用 DSH profile loader，使首次安装及符合条件的热更新无需替换桌面。

**将包安装视为激活。** 不含 bundle patch 的包不会通过 `dsh plugin add` 贡献 profile 层。明确的首次挂载工具校验字节，并记录 Loader 实际监视的配置行。

**假定所有旧桌面均能接受同一插件。** 相同源码版本提供兼容依据，但实际安装的运行时可能不同或不完整。检查验证接收方安装；未知或不兼容安装需要补充位置信息或进行原生升级。

**在更新器自身工具执行期间替换更新器。** 重载可能 dispose（资源释放）正在执行替换的操作。暂存自身更新且不修改被监视的 patch，使操作保有执行归属，直至外部流程在 Host 停止后安装。

**仅信任 HTTPS 和包名。** 分发错误或服务器遭入侵后，同名文件可能包含不同字节。固定目录密钥、已认证摘要及不可变组件目录将批准的操作绑定到所选字节。

**将成功写入 profile 报告为更新完成。** 有效的 patch 写入之后仍可能发生 Loader 失败。待处理状态将安装证据与实际激活分开，而绑定修订号的回滚保留无关变更。

## 后果

组件更新可以复用运行中的 DSH profile 及现有批准机制，不增加另一个应用进程或独立图形更新页。组件签名密钥形成独立的发布职责。初始目录仅包含更新器组件，不代表存在运行时或其他组件更新。

暂存的须重启更新需要外部安装流程；此插件不提供重启时自动应用。原生安装器执行及真实平台验收与已验证下载仍彼此独立。组件校验、首次挂载拒绝、修订冲突、回滚及批准拒绝需要针对性测试；将首次安装声明为已生效前，仍需实际 Loader 观测。

接入包的兼容证据区分源码对比与安装验收。对已发布标签的源码审计不代表每个旧安装包都已在各平台运行。原生回退流程联网准备经过验证的下载，将原生安装留给用户另行操作，保留当前对话所属的 Host。

# Agent Note: 在发布下载缓存前验证 Node 压缩包

Status: implemented

[English](2026-09-17-node-archive-integrity-and-recovery.md) | 中文

## 问题

首次启动预配在没有兼容主机运行时时下载对应平台的 Node 压缩包。把已有缓存文件名当成下载完成证明，会在中断后复用截断的字节。在校验压缩包前替换已安装 Node 目录，还会在解压失败时破坏可用运行时。

## 决策

桌面在 `runtime/config.rs` 中将所选版本和平台压缩包固定到官方 [Node SHA-256](https://nodejs.org/dist/v22.19.0/SHASUMS256.txt)。更改固定 Node 版本时必须审核对应摘要。镜像仅改变来源 URL。原生与 WSL 预配在复用前校验缓存，并在删除任何已安装 Node 文件前校验替代下载。

下载在缓存目录内使用 `tempfile::NamedTempFile`。数据流或摘要失败以及 future 取消都会释放私有临时文件，不替换现有缓存；校验成功后同步并原子保存替代文件。损坏的普通缓存文件触发重新下载。缓存符号链接或非文件会在读取目标前被拒绝。[源码预配决策](../feature/2026-08-14-cross-platform-desktop-source-provisioning.zh.md)继续负责捆绑包位置和运行时选择。

## 考虑过的替代方案

**从选定镜像获取摘要。** 被篡改的镜像可以同时替换压缩包和校验和。经过审核的摘要随可信桌面可执行文件分发。

**删除旧缓存并直接向最终文件名写入。** 失败会丢弃原有字节，并让下次尝试看见未经验证的文件。同目录临时文件提供限定作用域的清理和原子替换，无需另行定义部分文件协议。

## 后果

下载测试使用动态分配端口的本机 HTTP，并在取消前观测进度事件，覆盖有效缓存复用、损坏缓存恢复、截断响应、错误摘要、取消清理和符号链接拒绝。这些测试验证执行主机上的共享下载操作；Windows 替换语义、WSL 解压和干净安装后的首次启动验收仍需要对应平台观测。主机提供的 Node 二进制、依赖安装和操作系统发布者验证仍是独立检查。

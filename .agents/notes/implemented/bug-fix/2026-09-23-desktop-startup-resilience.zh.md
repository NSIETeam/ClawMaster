# Agent Note：让桌面启动和集成在降级状态下仍可用

状态：已实现

[English](2026-09-23-desktop-startup-resilience.md) | 中文

## 问题

桌面启动会修复所有 DSH profile，即使本次只需要 web Host，也会重新解析和下载依赖。因此，过期的可选 profile 或仓库网络问题都可能拖慢甚至阻断启动。首轮会话列表还可能在列表到达前清空持久化选择；审批服务短暂不可用时，RPA 插件也可能整体无法装载。

## 决策

桌面启动只修复 `profiles/web`，使用随包锁文件和有界的离线优先 pnpm 重试；其他 profile 留给显式插件维护。IM 默认配置加入持续重试和健康检查间隔。只有 ready 列表确认选中的会话不存在时才清空选择。RPA 只强制依赖工具注册表，因此审批服务降级时仍可执行只读检查；所有写操作仍使用现有审批能力，在没有授权时安全拒绝。

Tauri 壳仍使用内部 DSH web Host，因为它负责提供前端运行时；启动始终传入 `--no-open`，桌面启动不会打开外部 Web UI。

## 备选方案

**启动时安装所有 profile。** 这样 profile 看起来更整洁，但会让无关的可选状态成为启动依赖，并重复网络操作。

**让所有 RPA 操作都不需要审批。** 这会使写操作在没有独立授权时也能执行，违反现有的安全拒绝规则。

**移除 DSH web Host。** Tauri 前端由这个内部 Host 提供运行时；移除它会移除应用运行时，而不是移除外部浏览器路径。

## 结果

首次启动不再为无关 profile 下载依赖，也不再重新解析随包依赖图。离线或已有本地缓存时，安装会在有限重试内完成。重启时，首轮列表加载期间会保留当前会话。IM 临时断线会自动重连，无需手动点击。审批降级时，RPA 的发现和只读调用仍可用；改变桌面状态的调用继续要求明确授权。

## 验证

session-controller 客户端测试覆盖首轮列表期间保留选择和 Host 重连恢复。桌面默认配置与发布工作流测试通过，并验证 IM 重试配置和内部 Host 的严格启动方式。Rust profile 修复测试和 RPA Host 测试覆盖启动范围收窄及审批依赖可选化。

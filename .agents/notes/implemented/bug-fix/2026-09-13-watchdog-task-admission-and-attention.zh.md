# Agent Note: WatchDog 任务受理与待处理事项

Status: implemented

[English](2026-09-13-watchdog-task-admission-and-attention.md) | 中文

## 问题

管理任务说明可能在面板卸载时丢失。提示词响应不确定时，还可能留下已创建但没有明确重试入口的 Session，或因重试采用其他标识而重复受理工作。管理者需要区分等待其决定的请求和空闲 Session，同时避免将执行状态当作业务完成证明。

## 决定

[前端导航所有者](../../../../frontends/dsh/src/navigation.ts)在自身生命周期内保留任务目标、频率与未确认目标。切换设置、组件或 Session 会保留草稿。失败或结果不确定的提交复用已分配工作空间与 Session。提示词发出后，结果未确认时，表单与导航动作都会锁定目标和频率。重试保留相同提示词与 DSH 提交标识，即使界面语言已改变；既有 Host 受理实现对已接受请求去重。打开原 Session 可核查情况。发出提示词前失败仍可编辑草稿。确认受理后清空草稿并解锁。导航取消会阻止延迟选择和尚未开始的提交，不会撤回已经提交的请求。

[WatchDog 客户端](../../../../frontends/dsh/src/client.tsx)投影 DSH 待处理交互服务。审批、提问与计划复核请求在任务列表中优先显示，并可通过待处理筛选查看；打开条目会返回原 Session。“运行中”和“空闲”仍是执行状态。前端不会根据 Session 正文推断业务成功或失败，也不维护第二套审批队列。

[壳层决策](../feature/2026-09-12-clawmaster-shell-over-dsh.zh.md)继续负责工作空间分配与 DSH 运行时归属。[首次使用教程](../feature/2026-09-13-watchdog-first-run-tutorial.zh.md)单独负责管理介绍与阅读确认；阅读教程不创建任务。

## 考虑过的替代方案

**将草稿保存在面板内部。** 常规导航卸载面板时会丢失草稿，前端生命周期已覆盖这类用户操作。

**每次重试都分配新 Session 或请求标识。** 传输失败不代表请求被拒绝。编辑结果不确定的请求，可能在原任务仍运行时又追加任务。锁定输入并复用 DSH 受理标识可消除这类歧义，无需另建去重服务。

**扫描完整 Session 推导错误或完成状态。** 既有待处理交互能直接标识需要用户决定的事项。空闲状态和任意对话文本均不能证明管理结果。

## 后果

草稿保留覆盖面板导航，不跨页面刷新或应用退出。前端不增加持久草稿存储，也不充当业务完成的判定者。启动工作仍需明确操作；渲染、筛选和导航不发送模型请求。业务任务启动会通过所选 Session 提交已保存的任务简报，并使用持久请求标识。频率说明使用既有 Schedule 行为，不创建操作系统调度器。

[导航测试](../../../../frontends/dsh/tests/navigation.test.mjs)覆盖草稿保留、提交前失败仍可编辑、结果不确定时锁定输入、切换语言后保留重试标识，以及取消行为。[编译组件测试](../../../../frontends/dsh/tests/components-native.client.spec.mjs)通过已注册的 WatchDog 入口验证待处理交互，并记录两种语言。这些是合成源码与编译客户端检查；最终原生交互和真实提供方验收由桌面任务负责。

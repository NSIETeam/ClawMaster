# Agent Note: 命令回执保留经过认证的归属

Status: implemented

[English](2026-09-16-authenticated-command-receipts.md) | 中文

## 问题

命令标识符只能证明请求了哪个操作，不能证明请求者是谁。即使没有第二次写入，返回另一调用者的回执也会错误归属成功结果并省略审批。人类成员标识符与代理 Session 标识符属于不同命名空间；代理的归属还取决于发起成员。

## 决策

业务和任务回执绑定组织、参与者类型、参与者 ID、发起主体以及完整验证后命令信封的 SHA-256。重放前仍检查当前成员权限。权限版本、传输方式、调用 ID 和审批记录不属于稳定身份：这些事实的变化不会转移归属，合法重试也可以使用新的调用 ID。准备和提交阶段都检查绑定；新绑定与写入及责任记录在同一个 SQLite 事务中提交。恢复回执的请求哈希也包含发起主体。

数据库结构版本 5 的迁移创建独立的回执归属表，不从旧业务历史推测参与者。身份未知的维护写入和缺少归属的历史回执仍可读取，但不能授权重放。业务备份包含记录和审计数据，不包含经过认证的回执归属。恢复数据不删除已有归属；完整请求中的恢复代数阻止旧命令 ID 在恢复后获得新含义。冲突或缺少归属的回执返回 `command_conflict`；调用者必须检查当前状态，明确审阅新命令后才能使用另一标识符提交。

[任务身份决策](../architecture/2026-09-16-watchdog-task-identity.zh.md)继续负责角色检查和独立审批。[责任历史决策](../architecture/2026-09-16-enterprise-responsibility-history.zh.md)继续负责历史操作的归属。

## 考虑过的替代方案

**仅匹配命令正文。** 另一成员可能知道相同的正文和标识符；内容相同不能建立身份。

**用当前操作者回填旧回执。** 当前操作者不一定是原始参与者。拒绝归属不明的重放可以保留历史事实，避免重复执行结果不确定的写入。

**要求重试使用相同权限版本或审批 ID。** 当前权限必须重新检查，但已完成的命令已消费审批。绑定会变化的授权元数据会无谓阻断响应丢失后的恢复。

## 后果

HTTP 与真实 DSH ToolRuntime 回归覆盖成员变更、人类与代理 ID 冲突、代理发起主体重新绑定、修订改变以及数据库重开后的同主体重试。使用含漏洞基线的负向对照验证测试能发现未经授权的回执复用。迁移和恢复检查保留已有记录并拒绝缺少归属的回执。真实 Loader/AgentLoop 场景记录两种模型可见拒绝，并从持久化 JSONL 重建结果。这些检查证明本地授权行为，不证明已部署的身份提供方或多人运行时隔离。

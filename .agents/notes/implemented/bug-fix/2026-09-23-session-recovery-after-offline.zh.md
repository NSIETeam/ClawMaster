# Agent Note: Host 重连后恢复失败的会话窗口

Status: implemented

[English](2026-09-23-session-recovery-after-offline.md) | 中文

## Problem

桌面 Host 不可达时打开会话窗口，首次日志请求可能以 `gateway/internal` 错误结束。Host 后续恢复时虽然会刷新列表并恢复已有实时流，但这个失败的冷窗口已经没有可重连的流代，因此选中的对话会一直停留在错误状态，直到用户手动修复应用。

## Decision

建立新的 Host 连接代际后，Session Manager 只重试常驻 Session 中打开状态为 `error` 且错误为 `gateway/internal` 的窗口。重试复用已有的带代际保护的 `resync()` 路径；已经打开的窗口继续使用各自的流恢复机制。`session/not-found` 等协议或业务失败仍然展示给用户，不会自动重试。

隔离浏览器渲染验收会从验证脚本实际写入的 runner 临时目录上传证明文件；证明缺失现在会让工作流失败。

## Alternatives considered

**每次重连都重建所有常驻 Session。** 这样会产生不必要的历史读取，也会干扰本来可以由自身流恢复的健康窗口。

**重试所有 Session 错误。** 业务错误会被重复请求掩盖，永久删除的会话可能进入无休止的恢复循环。

**继续把渲染证明作为可选项。** 浏览器断言通过但截图没有被保存，会让发布验收记录不完整，并让路径错误继续被忽略。

## Consequences

仅因 Host 载体不可用而失败的会话，会在下一次成功连接代际建立后自动恢复，无需手动刷新。其他终止性错误仍会明确显示。GitHub 隔离安装任务现在会在浏览器证明无法留存时失败，因此成功任务必须包含可上传的渲染产物。

## Verification

Session Controller 客户端套件新增回归测试：第一次历史加载失败，建立新的连接代际后，同一会话第二次加载成功。桌面工作流回归测试检查临时目录上传路径和缺少文件时的严格失败策略。

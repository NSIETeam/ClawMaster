# Agent Note：企业备份工作进程在取消时保留授权检查与回滚

Status: implemented

[English](2026-09-16-enterprise-backup-workers.md) | 中文

## 问题

在 Host 上组装、克隆并序列化完整备份，会使内存和事件循环停顿随业务历史增长。把同一对象传给工作进程又会复制一次。审批等待后的恢复还需要当前权限、已复核的数据库版本，以及明确区分取消和成功回执丢失的机制。

## 决策

[备份 Host](../../../../frontends/dsh/src/enterprise-backup-host.ts)在读取请求体前限制入口，将内容写入私有文件，只向工作进程发送路径和小请求。只读工作进程逐条导出同一 SQLite 快照。导入准备逐行解析并规范化独占对象，保留记录、引用、审计连续性和回执内容校验。可配置的文件字节、并发作业、准备文件数量、工作进程堆与存活时间限制已接纳的工作；它们不对原生分配施加 RSS 硬限制。

准备文件属于唯一组织、操作者和发起成员。工作进程只有在精确审批通过后才能获得可写数据库目标，并在事务内比较恢复代次和修订。COMMIT 前会暂停，等待 Host 再次检查当前成员权限。在这段期间，普通写入遇到写锁竞争立即拒绝，保证 Host 能完成或取消工作进程。卸载和取消等待工作进程退出，其 SQLite 清理回滚未提交事务。

恢复成功、责任元数据与回执一起提交。回执绑定规范化备份摘要、已复核版本及可信所有者；重放不会再次替换记录。工作进程退出后，Host 先检查该回执，再报告取消。浏览器在面板导航间保留结果未知的请求，明确核对原命令，即使准备文件已被清除。刷新其他记录不能确定该修改的结果。浏览器重载仍会丢失内存中的待核对请求，需要人工检查持久记录。

可移植格式 1 仍为 JSON。尚未稳定的 HTTP 接口使用原文件准备和小型恢复回执，因此 Host、浏览器及打包的私有工作进程必须一起部署。同步存储方法只服务于维护调用者。[分页记录决策](2026-09-16-enterprise-paged-workspace.zh.md)继续约束普通读写；本记录负责显式文件操作。

执行器是固定的私有 Node 产物，不提供 package bin、公开 argv 或应用配置档。现有 DSH subprocess 服务提供数据流但没有 IPC 通道；Host 使用私有 fork，显式传递最小环境、忽略标准输入输出，并只通过 IPC 传递元数据。执行器不创建后代进程，释放存储前等待进程关闭，不导出通用进程启动 API。DSH 仍是应用启动器。

工作进程仅在 Host 最终授权检查之后追加成功责任记录。记录保留准确的已消费批准，以及该次检查观察到的策略版本；操作者、发起主体、组织或批准发生变化时，不能提交事务。

## 考虑过的替代方案

**通过工作线程共享 Host 进程。** 实测 Node 24 在工作线程堆上限为 32 MiB 时解析 JSON，会触发进程级致命 OOM，终止 Host，而不是产生可捕获的工作线程错误。私有进程隔离此类失败，退出后返回可恢复的存储错误。

**把完整备份克隆到工作进程。** 结构化克隆仍在 Host 上保留第二份全库分配，并在准备消息时延迟取消。

**发送中止消息后立即宣布取消。** 同步执行的工作进程要到工作完成后才能收到消息，可能在用户看到取消之后提交。等待终止并检查持久回执才能确定真实结果。

**删除校验以降低内存。** 这会放行不一致的引用和回执。原地逐行规范化减少重复保留的对象图，同时保留语义检查。

## 后果

[工作进程路由回归](../../../../frontends/dsh/tests/enterprise-backup-worker.test.mjs)覆盖真实 SQLite 事务、读取请求体前的字节限制、并发慢请求、过期、审批及最终提交时撤权，以及取消后独立写入者立即取得 SQLite 锁。[客户端测试](../../../../frontends/dsh/tests/enterprise-backup-client.test.mjs)丢弃已提交的响应，再恢复其回执，不覆盖后续编辑。[真实界面测试](../../../../frontends/dsh/tests/enterprise-restore.client.spec.tsx)覆盖文件准备、复核、取消与结果核对。[容量诊断](../../../../frontends/dsh/benchmarks/README.zh.md)使用编译的 Host 和工作进程产物测量三个档位；不包含安装平台与真实模型验收。

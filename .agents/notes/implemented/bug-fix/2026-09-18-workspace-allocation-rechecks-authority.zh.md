# Agent Note: recheck workspace authority before registration

Status: implemented

[English](2026-09-18-workspace-allocation-rechecks-authority.md) | 中文

## Problem

工作区分配会先创建目录，再由注册表将其加入 DSH。异步分配期间，成员资格或工作区类型授权可能被撤销。

## Decision

路由会在创建目录前检查经过认证的调用方及其请求的工作区类型权限，并在调用 `workspaceRegistry.create` 前立即再次检查相同权限。如果第二次检查拒绝访问或授权服务不可用，路由不会注册工作区，并会移除本次创建的空末级目录；已有目录会保留。共享工具桌面会串行执行授权、创建、注册和回滚，因此一个调用方的清理不会删除另一调用方已注册的工作区。最终检查之后的策略变化不在授权方提供的事务保证范围内。

## Alternatives considered

- **只在创建目录前授权。** 文件系统操作期间发生的策略变化仍可能导致未获授权的 Workspace 注册。
- **先注册再复查。** 路由尚未确认调用方仍有权限时，注册表就会暴露该资源。
- **拒绝时删除所有目录。** 共享或预先存在的工作区路径必须保留；清理仅限本请求创建且仍为空的路径。
- **不串行清理共享桌面。** 并发授权调用方可能先注册同一路径，之后被撤权调用方的回滚可能删除该已注册工作区。

## Consequences

- 最终检查观察到撤权时，Workspace 注册会被阻止。
- 授权服务错误仍按失败关闭处理；清理不会移除非空或预先存在的目录。
- 授权方与文件系统注册表没有共用事务，因此无法阻止授权返回后发生的策略变化。

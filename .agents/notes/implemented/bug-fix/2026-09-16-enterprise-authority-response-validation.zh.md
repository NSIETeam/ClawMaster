# Agent Note：校验企业权威服务响应

状态：已实现

[English](2026-09-16-enterprise-authority-response-validation.md) | 中文

## 问题

企业前端把认证、Session 所有权、成员资格和审批决定委托给 `GovernanceAuthority`。TypeScript 能描述这个提供方，但不能在运行时校验格式错误的响应。把错误输出当成普通拒绝会掩盖提供方故障，也可能让不同消费者采用不同的安全失败方式。

## 决策

`GovernanceAccess` 在使用每个非空的提供方响应前进行校验。主体必须包含组织、成员、参与者类型；代理主体还必须包含 Session ID。成员资格必须包含布尔型 active、已知角色、受限的策略版本和受限的资源标识符。审批响应必须包含受限的标识符。缺少响应仍表示未认证、未激活或未批准；格式错误的输出会产生稳定的提供方故障，路由消费者将其映射为服务不可用。提供方异常文本不会返回或保存。

校验放在共享的访问层，因此 HTTP、DSH 工具、任务负责人和审批提交使用同一规则。组织绑定、当前成员权限检查和独立审批仍由原有存储及服务负责；本修复不声称提供 OIDC 实现或已经部署的多人服务。

## 结果

格式错误的权威服务输出不能获得本地访问、伪装成企业权限拒绝，也不能提交变更。回归测试通过已注册的企业路由和隔离 SQLite 存储检查格式错误的 HTTP 主体、成员资格和审批输出，并直接检查格式错误的 Session 主体。现有组织错配和迁移测试继续负责持久化组织所有权。

# Agent Note: 已安装版本验收证据

Status: implemented

[English](2026-09-16-installed-release-acceptance-evidence.md) | 中文

## 问题

安装包构建、运行时冒烟检查和安装后的用户流程证明的是不同事项。单一绿色状态不能标识已观测的平台、签名产物、数据保留或真实用户路径。签名凭据和集成测试账号的缺失必须在发布证据中明确保留。

## 决策

[已安装版本校验器](../../../../apps/desktop-tauri/scripts/release-acceptance.mjs)将独立的 Apple Silicon、Windows、Linux AppImage、Linux DEB 和 Android 安装记录与精确候选提交及版本核对。它计算每份安装包和被引用证据文件的哈希。必需的安装、重启、恢复及支持旧版本升级场景分别保留结果。Android 自身承担明确的审批、取消和持久化观测，不继承桌面证据。

系统发布者校验与更新下载校验彼此独立。macOS 需要 Developer ID 及公证证据，Windows 需要 Authenticode 证据。缺少证书或设备时保留阻塞记录。可选集成没有通过证据就不能宣传为可用；账号测试需要明确授权及精确客户端版本。每个平台仍须完成真实供应商运行。

正常 CLI 拒绝不完整证据。只报告模式列出缺失项，不授权发布。模板不包含任何通过记录。校验器验证所保留的证据，不能证明人工声明的真实性；原生收集器和独立审核仍然必要。[验收参考](../../../../apps/desktop-tauri/acceptance/README.zh.md)负责收集器和产物要求。[发布命令决策](2026-09-15-desktop-release-native-command-failures.zh.md)继续负责工作流失败传播。

## 考虑过的替代方案

**把构建或解压产物当作已安装验收。** 解压产物不能覆盖安装权限、原生窗口启动、系统凭据或卸载语义。每种安装器都需要独立的干净环境观测。

**允许缺失字段代表通过或不适用。** 证据缺失会悄然缩小发布范围。只有明确标为试用或不可用的可选集成可以保留未验证状态；必需场景阻止准备就绪。

**从更新器签名推定代码签名。** 更新器密钥为 ClawMaster 认证下载内容，不建立 macOS 或 Windows 发布者身份，不能代替操作系统校验。

## 后果

校验器提供可重复执行的拒绝检查及所保留产物的完整性验证。测试证明缺失平台、过期源码、文件篡改、替代签名、遗漏场景及未授权账号声明会被拒绝，并覆盖真实 CLI 退出状态。它不创建证书、不执行设备验收，也不发布版本。发布工作流在生成更新元数据和上传版本前调用严格校验；其 shell 步骤回归拒绝缺失及不完整的 manifest。原生安装证据及其收集仍是关闭 Issue 或验收版本前的独立要求。

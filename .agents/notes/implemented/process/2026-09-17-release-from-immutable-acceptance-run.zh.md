# Agent Note: 仅从不可变候选 run 证据发布

Status: implemented

English | [中文](2026-09-17-release-from-immutable-acceptance-run.md)

## Problem

标签构建可以在同一工作流 run 中进入发布，即使该 run 尚未获得安装验收与集成证据。发布阶段重新构建也可能生成从未用于验收的安装包字节。

## Decision

标签推送和默认手动触发只构建并保留候选产物，不发布。单独的发布触发必须指定成功的候选构建 run，以及包含已审核验收清单和证据文件的完整提交 SHA。发布任务会将 GitHub run 的仓库、工作流、完成状态、结论、run ID 和源码提交与所选发布标签核对，从该 run 下载产物，并拒绝用证据文件覆盖原始产物。现有验收与最终资产校验器继续验证清单版本与提交、证据摘要、安装包摘要、构建树和最终发布文件集合。

发布任务使用 `desktop-release` GitHub 环境，供仓库管理员要求独立审核人。工作流不会为人工采集的观察结果生成密码学证明；验收校验器只能确认留存字节和声明结果。只有仓库配置了环境审核人，才能把这道门视为独立审批。

发布矩阵没有 Android 构建器。所需 Android 验收项仍不完整，在有受支持的构建和真实设备证据流程之前会阻止发布。当前托管构建配置也没有 macOS Developer ID 公证或 Windows Authenticode 凭据。

## Alternatives considered

**从标签构建任务直接发布。** 标签构建开始时，原生冒烟报告及外部设备、账号观察并不都已具备。该任务只能每次失败，或接受与安装包字节未绑定的证据。

**在发布触发期间重新构建安装包。** 即使源码提交相同，新构建也可能与先前安装和观察的安装包不同。因此发布按不可变 run ID 下载原始产物。

**把带校验和的证据当作观察属实的证明。** 摘要能发现文件被更改，但无法证明记录的观察真实发生。仍需独立环境审批和真实平台记录。

## Consequences

构建 run 不会自行发布。操作者在验收审核期间保留原候选 run，并在发布时提供不可变证据提交。缺少平台、签名、场景或集成时仍会阻止发布。环境保护配置、Android 构建支持、公证、Authenticode 和真实设备或账号验收仍需要外部配置或平台访问权限。

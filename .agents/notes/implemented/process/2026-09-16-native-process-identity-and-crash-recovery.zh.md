# Agent Note: 将原生验收绑定到进程创建身份

Status: implemented

[English](2026-09-16-native-process-identity-and-crash-recovery.md) | 中文

## 问题

此前的原生验收会保留数字 PID 和可执行文件路径，但报告没有说明这些身份从启动到就绪及最终取证期间保持不变。因此，复用的 PID 或被替换的可执行文件可能被误认成收集器启动的进程。

## 决策

macOS 与 Windows 收集器会在启动、就绪和最终取证时保留可执行文件路径及进程创建身份。如果 PID、可执行文件路径、父进程或创建身份在这些观测之间变化，校验器会拒绝报告。Windows 在清理期间保留已拥有的进程句柄；macOS 使用带身份的观测和回收路径。这些检查会阻止清理操作已经被复用的 PID。

桌面运行时状态已经在每次成功启动时发布新的运行 id，并在将运行标记为已停止前核对该 id。原生验收会在启动被中断时保留失败观测，后续启动则通过同一个桌面拥有的状态路径写入后继记录。真实平台上的崩溃或设备重启仍需要真实平台证据；单元测试和正常关闭运行无法证明这项结果。

## 后果

跨平台原生报告现在携带足够的进程身份信息，可以发现被观测运行期间发生的进程替换。这增强了安装和重启通道，但不会把进程探测当成发布者签名或设备证据。Developer ID 公证、Authenticode、Android 覆盖及真实设备上的崩溃恢复仍是完整发布矩阵的外部前置条件。

# Agent Note：Beta 版本发布证据门禁

状态：已实现

[English](2026-09-18-beta-release-evidence-gate.md) | 中文

## 问题

桌面 Beta 门禁必须验证用户实际收到的安装包和安装证据，同时避免每次 Beta 构建都被无关平台拖累，也不能削弱稳定版发布要求。

## 决策

精确匹配 `desktop-vX.Y.Z-beta.N` 的标签会选择 Windows x64 NSIS 和 macOS Apple Silicon DMG 构建任务。稳定版和其他预发布标签仍保留现有完整平台矩阵。Beta 与稳定版候选都必须提供安装验收、源码溯源，以及一致的 workspace 和 desktop 锁文件摘要。最终门禁会记录安装包大小并对照非阻断性的 20 MiB 优化目标；上传前验证完整校验和清单，再从 GitHub Release 下载文件并重新验证实际发布的字节和溯源信息。Beta 发布还要求通过 `CLAWMASTER_DOWNLOAD_PAGE_URL` 配置 HTTPS 下载页；发布前后都必须确认该页面展示候选版本标记以及两个候选安装包链接。

## 考虑过的方案

**所有 Beta 都使用稳定版平台矩阵。** 这会要求一个双平台桌面门禁也构建 Linux 和 Android，并可能被无关验证阻塞。Beta 通道改为只选择声明的 Windows 和 macOS 安装包，稳定版要求保持不变。

**将 20 MiB 目标设为硬性体积上限。** Issue 将包体积定义为优化目标。门禁会报告超出目标的精确字节数，并使证据收集不依赖于优化结果。

**发布后信任本地上传目录。** GitHub 可能保留过期或不完整的 Release 资产。下载已发布的 Release 并逐项比较文件和校验和，才能验证用户实际可以下载的内容。

## 后果

仓库变量 `CLAWMASTER_DOWNLOAD_PAGE_URL` 必须指向提供发布下载内容的 HTTPS 页面。页面必须包含 `data-clawmaster-release-version="<version>"` 和 Windows 安装程序、macOS DMG 的准确 GitHub URL。变量缺失、页面版本过期或缺少任一链接时，门禁都会失败。已配置的线上页面和平台安装验收仍属于外部发布证据；本地脚本测试不能证明这些条件已满足。

## 验证

发布矩阵测试证明精确 Beta 标签会选择两个构建任务，稳定版标签则保留全部平台。发布验收测试会拒绝缺失的平台证据、被修改的安装包、锁文件摘要不一致以及不完整的原生生命周期结果。包体积测试证明 20 MiB 目标只会产生报告而不会阻断。下载页测试会拒绝过期版本、非 HTTPS URL 和缺失的安装包链接。工作流测试要求安装验收，并在发布前验证准确的资产字节和溯源信息；实际 Release 工作流会在从 GitHub 下载资产后执行同样的验证。

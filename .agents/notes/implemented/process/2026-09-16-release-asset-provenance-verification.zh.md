# Agent Note: 在发布前验证资产字节和来源

Status: implemented

[English](2026-09-16-release-asset-provenance-verification.md) | 中文

## 问题

发布任务可以将验收清单绑定到标签提交，但最终发布目录还包含由不同任务组装的安装包字节、更新元数据、签名和构建记录。缺少目录级一致性校验时，过期校验和或不完整的公开构建清单可能进入上传步骤。

## 决策

`verify-release-assets.mjs` 在生成校验和后、发布前运行。它要求当前四目标更新集合、三个平台构建记录、验收清单和发布公钥，拒绝 Intel Mac 文件名、符号链接、缺失或多余的校验和记录、字节变化、其他源码提交或源码树、脏源码记录、不完整的组件／锁文件／补丁清单，以及指向其他目标集合或版本的更新 manifest。

校验器接受验收清单引用的证据文件作为发布资产，并将这些文件纳入校验和集合。它不会推断平台安装、发布者签名、设备覆盖或集成结果；`release-acceptance.mjs` 继续负责这些独立保留的观测。

## 考虑过的替代方案

**只保留工作流中的内联检查。** 内联检查能将构建记录绑定到检出版本，但不能将最终目录的校验和覆盖范围和清单字段作为一次操作验证。独立校验器为发布目录提供了可重复的只读检查。

**只重新生成校验和而不回读验证。** 重新生成 `SHA256SUMS.txt` 会掩盖已被编辑或不完整的暂存目录。校验器会读回生成的清单，并在上传前为每个保留文件重新计算哈希。

## 后果

发布资产缺失、多余、被编辑或关联到其他源码树时，发布会在暂存后失败。仅构建的手动任务不受影响，缺少外部验收证据仍由更早的验收检查阻止发布。校验器不会创建证书，也不会替代真实平台和账号测试。

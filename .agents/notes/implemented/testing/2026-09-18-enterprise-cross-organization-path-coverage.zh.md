# Agent Note：企业跨组织入口测试覆盖

Status: implemented

English | [中文](2026-09-18-enterprise-cross-organization-path-coverage.md)

## Problem

企业前端提供了可信的 `GovernanceAuthority` 接口，但仅测试接口本身不能证明已注册的业务入口会拒绝来自其他组织的主体。ClawMaster 企业协作 Issue #3 也要求验证附件访问，但此 frontend 当前没有企业附件服务路由或存储。

## Decision

治理集成测试通过 fixture 权威服务将主体认证为组织 `two`，并在组织 `one` 的数据上调用已注册的企业概览、命令、备份导出路由及 `enterprise_query` 工具。测试验证请求被拒绝、业务数据未变化、无法识别的本地桌面令牌被拒绝，以及命令 JSON 中附加的身份字段不能建立组织身份。现有工作区路由场景另行验证外部组织主体不能分配受管工作区。这些测试覆盖可信权威服务接口，不代表已实现或验收外部身份提供者。

前端没有已注册的附件路由或企业附件存储。`attachments.read` 仍只是未来消费者可用的授权词汇，不能让 DSH 通用附件能力自动具备组织隔离。部署方必须提供接入身份提供者的 `GovernanceAuthority`；企业使用之前，任何附件服务、IM 或插件消费者都必须实现并通过共享访问服务授权检查。

## Alternatives considered

**把 DSH 桌面令牌或调用方提交的成员字段当作企业身份。** 拒绝，因为本地应用凭据不能证明组织成员资格，而请求 JSON 由调用方控制。

**仅凭权限枚举就宣称附件隔离。** 拒绝，因为当前没有可执行或测试该权限的 ClawMaster 附件服务路径。

## Consequences

已注册的企业 HTTP、导出和工具入口现在有跨两个组织的回归测试；缺失的附件消费者与外部身份集成仍是明确的部署阻塞项。这些代码证据不能证明 OIDC 配置、生产身份提供者行为、IM/插件中介、真实企业部署、本地到企业迁移或桌面验收。

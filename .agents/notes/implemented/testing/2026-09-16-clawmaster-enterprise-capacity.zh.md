# Agent Note：企业容量使用隔离的编译工作进程测量

Status: implemented

[English](2026-09-16-clawmaster-enterprise-capacity.md) | 中文

## 问题

企业功能测试能证明记录和事务行为，但不能量化全量状态响应、审计读取或启动校验随数据增长的成本。一个有界查询不能证明调用方在其他位置没有读取全量快照。

## 决策

[所属模块的诊断](../../../../frontends/dsh/benchmarks/README.zh.md)使用与前端 Host 构建相同的外部包策略编译生产存储。新的普通 Node 进程读取合成数据库的独立副本；工作负载不涉及用户工作区、凭据或模型调用。准备数据和导入模块不计时。报告将源码和编译适配器标识为诊断证据，而非已安装版本。

默认三档为每个业务集合 100、1,000、10,000 条记录，审计条目为其五倍。程序在单个 SQLite 事务中插入确定性记录及对应审计行，然后通过生产初始化重新打开数据库，在测量前校验记录模式、外键、连续审计历史和责任历史。这样数据准备不占用接口计时，也不会把未经校验的行当作生产数据。存在响应时，每个被测终点均包含序列化。测量前执行 GC；观察内存时结果对象仍然可达。恢复保留输入备份。事件循环探针包含最后一段同步阻塞，报告明确排除浏览器输入和绘制。

## 考虑过的替代方案

**使用每条生产命令准备夹具。** 这会测量命令写入吞吐，而不是当前关注的读取、备份与恢复路径；对生成的数据库执行生产初始化仍会验证测量所用的业务和审计数据。

**立即设置固定时间预算。** 共享开发机器上的本地计时不足以确定稳定的 CI 噪声范围。本诊断报告全部样本，不给出性能通过结论。已有[必需基准通道](2026-09-04-session-open-performance-gate.zh.md)继续负责经过校准的 CI 预算。

## 影响

测量区分有界列表和回执结果与整库存储操作，揭示其绝对字节、延迟和内存成本。工作进程断言数据规模、已提交修改和完成恢复。夹具不测量生产命令吞吐。子进程两分钟超时限制失败持续时间，成功或错误后均清理独立目录。这些检查不能证明 HTTP 访问控制、浏览器响应性、已安装包的内存限制或任意企业数据规模的支持能力。

优化仍须包含所属功能测试、相同完成条件下的修改前后实测对比，以及负向对照。诊断本身不解决全量快照热路径、历史审计分页或流式备份要求。

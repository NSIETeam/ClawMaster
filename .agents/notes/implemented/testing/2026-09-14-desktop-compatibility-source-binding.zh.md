# Agent Note: 将桌面兼容性测试绑定到已准备的源码

Status: implemented

[English](2026-09-14-desktop-compatibility-source-binding.md) | 中文

## 问题

工作树变化时，已安装的插件目录可能保留较早的 DSH 产物。仅因该目录存在就选择它，会使兼容性测试在没有检查修改后运行时的情况下通过。手动保留的原始包目录也会让检查依赖另一位开发者的临时文件。

## 决策

桌面 `test:compat` 命令在获取依赖前校验当前已准备构建的来源记录和未安装包的摘要。它将已验证载荷复制到私有临时目录，按锁文件安装依赖而不执行生命周期脚本，并在解包前按已复核哈希检查固定版本的 registry 压缩包。测试接收明确的产物目录；路由测试不隐式优先选择打包目录。运行器在测试后重新检查源码来源记录，并在完成或失败时删除自己的临时目录。

## Alternatives considered

**优先选择任何现存的打包运行时。** 目录存在不能证明产物新鲜，也不能证明它对应修改后的源码。

**复用未记录的临时包目录。** 其内容和可用性无法支持可重复的验收命令。

## Consequences

兼容性测试需要完成准备，并提供网络、pnpm 和 tar。结果覆盖包安装及脚本化运行时兼容性，不覆盖真实记忆捕获与检索、IM 送达或原生安装。压缩包替换的负向测试纳入 `test:bundle`；现有来源记录测试拒绝源码变化和产物替换。

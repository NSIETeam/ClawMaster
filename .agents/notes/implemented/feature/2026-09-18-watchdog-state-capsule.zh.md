# Agent Note：WatchDog StateCapsule 沿用持久任务历史

Status: implemented

[English](2026-09-18-watchdog-state-capsule.md) | 中文

## 问题

应用重启后恢复工作，需要一份由现有组件持有的记录，整合任务上下文与安全续作所需的状态。Session 日志保留模型可见事件，任务修订则拥有业务目标、审批状态和证据。

## 决策

StateCapsule 存储在现有 WatchDog 任务行及不可变任务历史中。每条记录包含决策、文件哈希、验证结果、未完成动作和记忆 ID；目标及审批状态从任务派生，并随每次任务修订刷新。用户记录按已认证主体隔离。会话记录要求 Session 已关联任务；项目记录要求已注册工作区中包含关联任务的 Session。读取和命令响应按所有者过滤，并重新核对相关 Session 或工作区关联。

胶囊 schema 不含凭据字段，也不增加凭据导出路径。读取旧任务行时，胶囊列表为空。通过代理工具修改胶囊仍受现有一次性审批流程和任务修订检查约束。已认证主体标识在权威服务响应、任务成员负责人、提交者字段、胶囊所有权和持久责任身份中共用 1 至 128 个 UTF-16 代码单元的不透明 Unicode 规则；这允许邮箱标识通过校验，但不放宽身份的建立权限。各处使用同一个校验器，负责人字段不会重新收窄字符范围。

## 影响

恢复时读取任务当前修订及历史，因此不需要另建独立存储，也不会声称恢复从未写入 Session 日志的状态。通过任务关联 Session 确认工作区成员关系；按主体隔离可防止同一组织的其他成员读取胶囊。存储的自由文本不会扫描机密；调用者不得在笔记、决策、理由或摘要中填写凭据。

聚焦回归测试覆盖重启持久化、任务审批状态刷新、跨主体过滤、Session 与工作区范围检查、未知凭据字段，以及既有 DSH 工具行为。

## 考虑过的替代方案

**建立独立的 capsule 数据库。** 现有任务行和不可变历史已经拥有任务上下文与修订。第二个存储会引入跨存储排序和恢复规则，却不能建立更强的事实来源。

**在每个 capsule 中复制全部任务和 Workspace 详情。** 这些事实会独立变化，副本可能过期。实现每次都会从当前权威记录派生目标、审批、Session 和 Workspace 关联。

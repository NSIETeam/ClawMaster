# Agent Note: 持久化 ClawMaster 笔记与显式写入

Status: implemented

[English](2026-09-13-clawmaster-notes-vault.md) | 中文

## 问题

新用户需要无需安装外部编辑器的笔记库。智能体写入和并发编辑不能静默覆盖工作成果，也不能把版本冲突转变为删除。

## 决策

[笔记组件](../../../../frontends/notes/README.zh.md)在可配置的用户目录管理普通 Markdown 文件。组件复用 DSH 鉴权、工具类型、审批和侧栏注册，不引入另一台服务器。每次智能体改动都要求一次性批准；卸载会取消等待审批的操作。

协作写入者通过现有跨进程文件锁串行执行版本检查和写入。原子替换保护已保存内容的完整性；不覆盖发布保护已有目标。组件拒绝链接后代路径。共用文本解析使 Node 文件系统代码不进入浏览器。

侧栏关闭没有可拒绝关闭的回调，因此客户端在插件内存中按会话保留草稿。冲突保留草稿和磁盘内容；显式重新载入和删除均要求面板内确认。

起草与写入之间还有一步审阅。`notes_propose` 把草稿连同所依据的修订号保存在笔记库中被忽略的 `.clawmaster/` 目录下并返回行级 diff，全程不触碰任何笔记，因此无需批准；`notes_write` 的 `apply-proposal` 与 `discard-proposal` 负责落定。应用受修订号保护，期间被改动过的笔记会被拒绝而不是被覆盖，且建议保留下来供重试。diff 由一个有界、无依赖的行级 diff 在 host 端计算，因此模型与用户看到的是同一份内容。

完成的工作通过一条合成条目变成笔记：`notes_digest` 接收「做了什么」以及可选的决策、证据与下一步，链接到匹配的项目笔记，并在一次写入中把带日期的小节追加到日记。把它安排在任务结束时触发属于 WatchDog 任务层，而不属于本模块。

版本请求按需扫描文件元数据，并合并并发扫描；组件不使用原生监听或后台定时器。版本同时包含待审建议摘要，因此建议变动不依赖笔记变动即可刷新。扫描失败会报告给请求，允许重试；未保存草稿继续保留。

面板的观感对齐宿主自带的文件管理器，而不是一个通用列表——侧栏标签页若自创一套尺寸就会显得是外挂上去的。行高 34px、图标间距 6px、行内缩进为 `depth * 22 + 6`，文件夹行使用加粗标签字重，悬停使用交互色，打开的笔记使用业务色底——这些数值取自 `dsh-better-sidebar` 的资源管理器样式。`src/tree.ts` 由笔记 id 推导出文件夹，使面板真正具备层级；`src/icons.tsx` 在同一套 16px 网格上提供内联 SVG 图标，因此模块仍然不携带任何位图资源。Obsidian 的 `app.css` 提供更细的线索：13px 的界面字号体系、弱化且带字距的小节标题、安静的未保存标记，以及渲染视图的正文排版。

## 考虑过的替代方案

要求安装 Obsidian 会排除全新安装场景。独立 HTTP 服务器会重复实现鉴权。盲目覆盖或自动冲突恢复会丢失用户意图。持久化草稿数据库引入另一份内容权威，暂缓实现。

## 后果

已保存笔记仍是可迁移的文件，未保存草稿不能跨进程退出保留。文件锁依赖协作，不能提供对恶意写入者的操作系统隔离；崩溃持久性和遗留锁恢复是明确的[限制](../../../../frontends/notes/README.zh.md#known-limitations-and-deferred-work)。创建和重命名需要硬链接。

## 验证

`npm --prefix frontends/notes test` 先构建再运行存储与主机测试，覆盖并发写入、路径限制、读写预算、建议漂移、批注、审批拒绝、卸载与按需刷新。产物套件直接加载 `dist/index.js`。

`npm run test:notes-client` 构建后在 jsdom 中运行编译客户端测试，覆盖草稿保留、显式丢弃、建议加载失败重试、批注、乱序读取与版本冲突。运行器固定 `NODE_ENV=test`，保证 React 测试接口可用。

真实浏览器与最终安装版界面验收独立于 jsdom 和类型检查；需针对重新生成的安装包执行。

`npm --prefix frontends/notes run typecheck` 检查严格类型；`node frontends/notes/scripts/build.mjs --check` 检查产物新鲜度。

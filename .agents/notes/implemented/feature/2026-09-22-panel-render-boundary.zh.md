# Agent Note：让失败的面板可见，而不是变空

Status: implemented

[English](2026-09-22-panel-render-boundary.md) | 中文

## 问题

产品前端原本没有任何东西接住渲染错误。渲染中抛错的组件会连同它上方的一切一起从树上消失，于是受影响的区域渲染成「什么都没有」：空白的主面板、空白的侧边栏组件，或者——当抛错发生在 shell 自己的子树里时——整窗空白。本产品此前的空屏事故起因在 Host 而不在 React，但前端没有第二道防线，而它自己的面板体量已经足够大：任何新的渲染缺陷都会变成一块没有任何信息的空白面。

## 决策

`frontends/dsh/src/RenderBoundary.tsx` 是一个错误边界，它把它包裹的子树替换成一条可见提示——写明是哪个面板、错误是什么——并提供「重试」，重试会清掉已记录的错误、让子组件重新渲染。`client.tsx` 把它注册到 shell 上的每个面都包了起来：主面板、引导设置面板、设置区块、每个侧边栏模块、每个模块的设置面板，以及 CRM 与 ERP 标签页。包装只有一个本地辅助函数，所以新增注册点不会在无人察觉的情况下漏掉它——除非有人显式删掉那行调用。

兜底文案和其它产品文案一起放在 locale 字典里，因此它遵守与它所替换的面板相同的语言规则。边界会把接住的错误与组件栈打到浏览器控制台，因为屏幕上那条消息是给用面板的人看的，而控制台才是排查的起点。

## 影响

某个面板的渲染故障不再清空整个窗口，也不再隐藏到底是哪个面板出错。边界只接渲染阶段的抛错：事件处理器里抛出的错误、Promise 拒绝，以及边界之上 shell 自身代码里的失败仍会继续向上传播，本笔记不声称覆盖它们。

「重试」是用同一份状态重新渲染同样的子组件。当成因是持续存在的数据形状问题而不是偶发问题时，边界会重新落回提示而不是陷入循环；但一个数据永久畸形的面板会一直停在提示上，直到那份数据改变——除了重试之外没有自动恢复。

`frontends/dsh/tests/render-boundary.client.spec.mjs` 覆盖四种情形：提示写明失败原因；失败边界之外的兄弟面板照常渲染；成因消失后重试可恢复；没有抛错时子组件原样渲染。该 spec 已登记进 `tests/vitest.navigation.config.ts`，因为一个不在那份 include 名单里的客户端 spec 根本不会运行。

# Agent Note: 可选微信 MCP 审批

Status: implemented

[English](2026-09-15-wechat-mcp-approval.md) | 中文

## 问题

个人微信自动化和公众号草稿功能涉及私人数据与外部写入。MCP 工具注解不能授权这些操作，可扩展的执行前监听器也可能短路其他监听器。

## 决策

[可选配置](../../../../apps/cli/config/examples/wechat/README.zh.md) 复用 MCP 客户端，使用独立命名空间、固定顶层包版本和本地审批插件。插件将每次审批授权绑定到执行对象与序列化参数；只收紧权限的工具守卫在执行前消耗该授权。未知工具名称默认拒绝。每次调用都需审批，包括桌面读取。配置禁用自动重连，不加入默认配置。

[RPA 恢复决策](2026-09-14-clawmaster-rpa-recovery.zh.md) 仍然负责原生 RPA。这些集成不替代它。该决策中对运行时前置条件的顾虑不禁止明确启用的集成；集成开发主机已安装 `uv`，但其他环境仍需操作者自行准备。

## 考虑过的替代方案

**仅提示词审批：** 当策略监听器放行调用时，提示词和 MCP 注解不能阻止执行。最终守卫负责强制检查本地授权。

**自动启用：** 操作者选择账号前，启动过程就可能下载依赖或请求操作系统访问权限。显式配置保留操作者控制权。

**广泛的账号管理：** 文颜覆盖文章草稿，不覆盖全部公众号 API。尚无证据表明这里需要更多操作，增加大型账号管理服务只会扩大凭据暴露范围。

## 后果

该集成是源码配置，不是已安装的桌面发行版。无密钥测试验证策略结果、一次性授权、资源释放与 Loader/MCP 工具发现；不能证明真实账号操作或完整录制的 agent（智能体）会话场景。外部服务依赖没有完全锁定，也未进行沙箱隔离。写入结果不确定时，操作者先检查外部账号再重试。两种集成都需要单独进行账号验收，不得提交凭据或私人聊天。

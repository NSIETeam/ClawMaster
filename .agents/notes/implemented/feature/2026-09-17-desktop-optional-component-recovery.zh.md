# Agent Note：桌面可选组件恢复

Status: implemented

[English](2026-09-17-desktop-optional-component-recovery.md) | 中文

## Problem

单个功能组件缺失或故障可能阻止桌面 Host 启动，导致 ClawMaster 的其它功能也无法使用。

## 决策

功能组件不可用时，ClawMaster 仍保持桌面核心可用。配置准备阶段会逐组件校验可选补丁、预设和组件自有存储；遇到无效组件时会跳过它并记录故障。配置为 `optionalClientPackages` 的缺失依赖不会触发整个 Web 配置的安装修复；桌面原生启动会在预加载迁移之前，按稳定的可选包清单识别旧 Web 配置。Host 恢复会识别 import、apply 和 pending-loader 诊断，再仅禁用白名单内的功能条目后重试。更新维护器缺失或运行失败时，启动会保留所有更新日志，记录更新是否待恢复或状态不可读，并继续启动核心 Host；维护恢复之前不会应用该更新。浏览器功能客户端使用独立启动脚本，可选性会传递给依赖可选动态模块或服务注入的非核心消费方；移除循环依赖的可选适配器后仍会保留它的可选身份，确保更深层消费方继续按可选处理。必需客户端先激活并打开界面，可选客户端随后在后台激活，因此停滞的功能不会阻止核心界面启动；可选预取不会拖住必需启动阶段；启动最终失败的可选 fiber 会在故障确认后移除。缺失或格式错误的作者 source map 会退回 identity map，不会禁用客户端。格式错误的工具 schema 会按工具隔离，其他已注册工具仍可使用。主前端、桌面策略、Guard、权限和审批条目保持必需。

## 考虑过的替代方案

拒绝在启动错误后禁用所有加载器条目，因为这可能让安全组件损坏或缺失的应用看起来仍然成功启动。拒绝在创建配置文件前要求每个已打包的功能包都通过校验，因为笔记、Office、连接器或更新器缺失时，不应阻止 ClawMaster 的其余部分打开。

## 后果

可选组件不可用时，不会出现在活动桌面配置中；后续启动通过校验后才会重新加入。缺失可选客户端依赖时不会为了修复整个 Web 配置而阻止 Host 启动；配置会保留完整可选分类，原生启动也会处理旧版已删除可选 bundle 行、但仍保留依赖记录的 Web 配置。必需依赖仍使用常规修复流程。路由预设无效时不会覆盖用户文件，也不会阻止其他功能启动；Loader 组合阶段已被拒绝组件的预设无法禁用其他组件。IM 工作区路径冲突时会禁用 IM 并保留原路径。可选插件激活失败时，本次恢复启动会禁用它，桌面外壳会提示其加载器条目 ID。各平台的已安装验收必须验证应用仍保持打开、受影响功能明确显示不可用、核心会话及其他无关功能仍可继续使用。核心 bundle 与可选客户端分开组成脚本批次。格式错误的工具 schema 不能污染模型请求或执行入口，健康工具仍可调用。新增桌面功能时必须明确它是否可选；如果适合启动恢复，还必须把加载器条目 ID 加入 Rust 白名单。核心应用与安全条目仍保持失败即拒绝。

## 验证

`desktop-defaults.test.mjs` 验证缺失、版本错误、补丁格式错误、预设冲突和组件存储路径冲突只会跳过对应的可选组件，前端包缺失仍会失败；同时验证被排除组件仍保留可选分类，Loader 组合阶段被拒绝的组件不会误删可用更新器。Rust 配置测试验证当前可选元数据，以及旧版只剩依赖记录、没有可选 bundle 行的 Web 配置，都能避免为缺失功能包安排整个配置的安装修复；缺失的必需依赖仍会安排修复。组件维护测试验证缺少或运行失败的维护器在无更新、更新待恢复和恢复日志不可读时均允许启动；待处理或不可读日志的字节保持不变。客户端模块和启动测试验证可选脚本隔离、动态模块消费方的可选性传递，以及移除失败可选项后核心启动成功。工具测试验证格式错误的 schema 不会进入 Native 投影、直接派发或 PTC 绑定，同时健康工具保持可用。Supervisor 测试验证可禁用可选集成，同时不能禁用前端、Guard、sandbox、approval、permission 和未知条目。各已安装平台上的恢复流程，以及每个被禁用功能的用户可见状态，仍属于桌面验收范围。

# Agent Note: ClawMaster 将 DSH 凭据保存在操作系统中

Status: implemented

[English](2026-09-18-clawmaster-os-credentials.md) | 中文

## 问题

桌面 DSH 配置中启用的凭据提供方，会把模型密钥和插件授权以明文保存在 YAML 文件里。基于文件的提供方也可能通过环境文件和 Windows 到 WSL 的启动路径传递凭据，使秘密暴露在操作系统凭据保护之外。

## 决策

桌面配置使用 `@clawmaster/dsh-credentials-keychain` 替换 DSH 的 `credentials` 服务。DSH 模型适配器和插件消费者继续使用 `ctx.credentials`；此提供方通过专用 `clawmaster-credentials/1` 继承管道协议向 Tauri 宿主发送请求。宿主将值保存在 macOS 钥匙串或 Windows 凭据管理器中，并固定原生服务标识。提供方只在 `$DSH_HOME/.credentials-index.json` 中保留凭据记录的名称与类型。

首次启动时，桌面 supervisor 会在后台线程中把继承的秘密环境变量复制到操作系统存储，并使用原子化的“仅不存在时创建”操作，因此安全存储锁定或不可用不会拖慢 Host 启动。提供方会从旧凭据文件，以及启动目录和用户目录中的 `.env` 文件导入支持的记录，并回读验证。WSL 启动也会接收桌面主目录解析器选定的规范 Windows DSH 主目录；提供方通过继承的宿主 broker 读取其中的旧文件，只有在安全存储验证成功后才删除它们，不会把凭据文件复制进 Linux DSH 主目录。即使并发迁移也不会替换已有的非空值。只有所有秘密都验证成功且记录元数据已提交，才会删除旧来源；dotenv 清理只删除解析出的秘密赋值，并保留其他全部字节。链接、格式错误、超大或无法读取的来源都会保留。安全存储或迁移失败只会记录不含值的警告，不会阻止 DSH 配置启动；需要安全存储的操作会向调用方报告失败。

## 已考虑的替代方案

**保留 DSH 文件提供方并加强权限。** 文件模式和 ACL 对静态秘密的保护不如操作系统凭据 API 直接，也会继续将明文秘密文件作为真实来源。

**只迁移模型密钥，将插件授权留在 YAML 中。** DSH 消费者共享同一个凭据提供方，而且授权记录也含有令牌；分开存储会保留原有暴露问题并重复实现迁移行为。

**让 Node 提供方直接调用操作系统凭据 API。** 这需要在 DSH 运行时中引入平台专用 Node 依赖，并让核心包负责桌面平台 API。现有 Tauri 宿主才是平台能力的所有者。

## 结果

实际模型请求会通过操作系统存储解析凭据，同时保持 DSH 消费者 API 不变。安全存储不可用时，桌面应用仍可启动；模型请求与凭据编辑会在需要该存储的凭据操作处失败。如果验证或安全清理失败，旧明文来源可能继续保留；用户必须先处理警告，才能删除源文件。WSL 模式依赖 Windows 宿主 broker 和可访问的 Windows 盘符挂载。独立 Linux 支持，以及 macOS 和 Windows 打包应用的原生验收，都需要单独实现宿主能力并执行平台测试。

## 测试

提供方定向测试覆盖专用线协议前缀与请求/响应、原生错误脱敏、dotenv 清理、格式错误 dotenv 保留、安全存储不可用时仍能启动、拒绝链接文件，以及从明确指定的 WSL 可见 Windows 主目录迁移而不在 Linux 主目录产生凭据副本。Rust 测试覆盖 WSL 启动时传递来源路径。这些测试无法证明打包应用中的钥匙串或凭据管理器原生行为，也无法证明所有 WSL 自动挂载配置均可访问。

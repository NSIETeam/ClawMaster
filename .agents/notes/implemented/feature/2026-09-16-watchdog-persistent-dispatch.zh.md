# Agent Note：不接管冷会话的 WatchDog 持久派发

Status: implemented

[English](2026-09-16-watchdog-persistent-dispatch.md) | 中文

## 问题

会话内提醒无法独立于执行对话报告 Host 停止，也不能协调竞争的产品工作进程。入队与确认之间崩溃还会留下执行歧义；对于任意 agent 副作用，自动重试无法安全消除这一歧义。

## 决策

[WatchDog 调度所有者](../../../../frontends/dsh/scheduling/README.zh.md)在组织绑定的 SQLite 账本中持久化不可变计划、有界实例生成、单次授权、隔离租约与独立工作进程心跳。DSH Schedule 保留时间校验与固定频率计算；DSH Jobs 保留执行者归属和取消能力。交付仅使用已经在线的根 agent 及公共持久收件箱。不扫描会话、不隐式恢复、不安装后台服务，也不转移凭据。

每个实例都要求显式审批。对话工具使用 DSH 回合内审批服务；认证的人类命令持久化具体实例授权。企业派发在入队前重新检查发起成员、委派资源权限和独立审批。保存的实例标识将授权与模型可见输入绑定。只读计划、实例和历史分页按最终 HTTP 或 DSH 封装的字节预算接纳完整记录。独立工作进程游标与全账本状态计数使心跳行位于后续页时仍保持可观察性。

会话忙碌时的接纳保留失败次数预算及原截止时间。DSH 维护任务同步取得执行资格；仅凭公开的空闲状态无法排除其他维护任务。企业审批消耗具有独立的持久派发前标记，因为身份服务与实例账本无法原子提交。任何已标记领取的中断都要求重新审批，包括租约恢复；自动重试不能假定原授权尚未使用。

入队前先写入持久屏障。此后缺少确认时保持不确定状态，必须由人审计确认或取消，不能重放。该协议优先防止自动重复，不将跨 SQLite 与会话存储的事务伪装成原子操作。派发完成只记录输入持久性；业务验收仍由独立机制负责。

管理面板将成功回执绑定到对应命令标识。未确认请求在面板导航期间保留完整载荷，防止第二条命令悄悄替换第一条。人工处理不确定状态需要确认已核对会话并填写理由；面板渲染和工作进程观察都不授予执行权限。输入校验失败后仍可编辑；缺失或不相干的回执保持未确认。

读取状态后，如果仍有有效计划但没有在线工作进程，面板会显示应用内告警。告警指出投递中断，但主机离线时不会通知运维人员。

## 考虑过的替代方案

扩展核心 Schedule 以唤醒冷会话会违反其活动根 agent 归属规则。替换 Jobs 会重复实现取消与卸载。不确定入队的自动重试可能重复产生外部影响；将健康工作进程或完成派发解释为业务成功会隐藏失败。独立数据库副本无法提供分布式租约，不属于本部署模型。

## 影响

Schema 2 要求升级前停止所有工作进程。未停止的新鲜心跳会阻止迁移；既有审计行与命令回执完整保留。旧版已领取实例要求审批恢复，因为 schema 1 无法区分尚未使用的授权与入队前已经消耗的授权。SQLite 版本递增无法撤销现有连接，因此运维人员必须停止旧工作进程，不能滚动升级。

共享同一本地数据库的工作进程必须具有一致的组织和部署限制。审批缺席、根 agent 离线、接纳预算耗尽与租约过期都有明确有界的结果。任意模型副作用仍需自己的幂等性与审批。已安装桌面的休眠唤醒、服务器运维与外部交付需要单独验收证据；合成模型与临时进程测试不能证明这些结果。

## 验证

[存储测试](../../../../frontends/dsh/tests/watchdog-schedule.test.mjs)覆盖有界漏跑、夏令时校验、命令回执、组织隔离、到期、租约隔离、滚动接纳，以及两个真实进程在单次副作用记录后崩溃的情形。[Host 重放](../../../../frontends/dsh/tests/watchdog-schedule-host.scenario.mjs)挂载正式 AgentLoop、Jobs、审批与 JSONL 持久化，验证单次持久派发、审批缺席、落盘期间的委派撤销、不确定状态和取消。[管理面板测试](../../../../frontends/dsh/tests/schedule-board.client.spec.mjs)验证有效计划没有在线进程时显示告警，并在工作进程心跳恢复后清除告警。Host 重放的包内夹具固定预定模型输入，不依赖当前墙钟。

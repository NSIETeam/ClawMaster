01 / 更新内容

更新来源更明确，窗口操作更顺手。

服务器更新与桌面修复

桌面优先从 ClawMaster 更新服务器检查正式版本，GitHub 作为备用来源。macOS 红绿灯占用独立标题栏，会话、侧栏与插件内容从下方开始。

按任务使用微信资料

macOS 新增每次单独批准的微信读取工具。AI 可以请求读取你已打开的聊天中有限的可见消息，用于整理本次任务。

Windows 修复更新文件缓存复用与知识索引路径匹配；Linux 改用系统密钥服务保存本地执行记录的加密密钥。安装包包含匹配平台的本地执行程序，继续保留笔记批注、WatchDog 业务审批、Office 保存冲突保护与重新启动修复。

0.2.2 提供 Apple Silicon Mac、Windows x64、Linux x64 AppImage 和 DEB。macOS 集中维护 Apple Silicon，以减少双架构安装包、原生组件适配与测试的维护成本，因此不再提供 Intel Mac 新安装包。Intel 用户的旧版入口与后续支持说明见官网下载区的维护范围说明。安卓独立 Agent 已发布 0.2.2，新增文档工作区与后台任务，使用单独的 APK 和发行说明。

02 / 安装与数据

替换应用，保留工作资料。

  1. 保存正在编辑的文件，等待任务结束，正常退出 ClawMaster。若关闭窗口被设置为最小化到托盘，请从应用菜单或托盘选择退出。
  2. 备份原有模型配置、会话、笔记库、业务工作区和 WatchDog 企业数据。不要用会清理应用数据的卸载器，也不要把密钥放进对话或公开文件。
  3. 从官网下载区选择对应安装包，按卡片中的 SHA-256 核对文件。macOS 安装到原来的应用位置，避免留下两份同名应用；Windows 和 Linux 使用对应安装器升级。
  4. 打开 ClawMaster，等待运行环境准备完成。首次准备仍需联网；保留原 DSH 主目录后，已有模型配置与会话可以继续使用。
  5. 查看历史会话、WatchDog 任务和需要的文件，再正常退出并重新打开。安装包版本正确、界面能打开与模型能实际回应，需要分别确认。
升级完成应看到

应用为 0.2.2，原有资料仍在；WatchDog 显示已连接，退出后能够重新打开。已连接只说明界面与运行时相连，模型凭据与额度还需通过实际任务确认。

管理人员：需要备份哪些数据？

保留实际使用的 DSH 主目录（常见为 ~/.dsh），包括凭据、设置、会话、插件配置和整个 watchdog 目录。macOS 还需保留应用支持目录、外置笔记库及系统钥匙串。从 0.2.0 等旧版升级时，旧格式的企业数据库会迁移；回退到 0.2.0 时，需要同时恢复升级前的数据库备份，不能只换回旧应用。

03 / 更新方式

检查、下载与生效，分别确认。

桌面打开后会后台检查正式版本。你也可以从托盘选择检查更新，先确认下载与签名校验，再单独确认安装和重启；取消后当前应用继续运行。后台检查只读取版本信息，不会自动替你批准安装。

在会话中输入 /updates，或请 AI“检查当前可用更新，只查看信息”，可以查看更新组件提供的结果。它不会因为检查而下载或改动文件。没有该命令时，先核对更新组件是否已加载。

根据返回状态，判断下一步
更新类型如何生效
允许热更新的组件批准具体版本后，下载并校验，交给运行时加载；仍需确认加载成功和功能可用。
显示“已暂存”的组件文件已准备，尚未替换。更新器自身也属于这一类，需在运行时停止后另行安装；只重启应用不会自动完成。
DSH 核心与桌面外壳仍需桌面安装流程。插件下载好文件，不代表原生安装已经完成。

以前通过接入压缩包安装的更新器会保留版本、配置与停用选择，不会被重复安装。旧更新器需要单独升级后才能使用新通道；首次安装接入包不能替换已有更新器。若旧版查不到 0.2.2，可以从本页官方安装包升级桌面。

组件是否能更新，取决于服务器实际发布的目录和当前运行时兼容性。提供更新入口不代表所有 DSH 组件都已上线独立更新。

04 / 微信逐次授权

先选定聊天，再批准这一次读取。

此功能需要已登录的 macOS 微信和系统辅助功能权限。它是读取你选定聊天的工具，与 IM 机器人登录是两种独立功能。当前不支持 Windows 或 Linux 的个人微信读取。

  1. 先在微信里手动打开一段适合测试的聊天，让目标消息在窗口中可见。准备完整显示标题；群聊需要包含标题上显示的人数后缀。
  2. 回到 ClawMaster，说明要读取的标题、条数与用途。建议第一次使用少量、不含敏感资料的测试消息；单次可请求 1 到 50 条可见文字条目。
  3. AI 发起读取请求后，核对审批卡片上的聊天、数量和用途。每次读取都需要单独批准；取消、拒绝或更换参数后，原批准不能继续使用。
  4. 批准后保持目标聊天和窗口位置不变，等待返回。标题不匹配或微信界面无法识别时，读取会停止并说明原因。
  5. 将结果与当前可见消息对照，再用于整理待办。可见消息和辅助功能文字不等于完整聊天记录，不应据此推断未显示的上下文。
试用任务示例

“请使用微信读取工具，申请读取我已经打开的聊天『填写完整显示标题』中最多 5 条当前可见消息，整理其中明确提到的待办。先向我申请本次授权，不发送消息，不读取其他聊天。”

读到的消息会进入当前会话、会话记录及你配置的模型服务，用于本次任务。请在批准前确认资料范围和模型服务；不要把这个功能理解为消息始终只留在微信或本机。

读取器不自动切换聊天、不翻页、不读取数据库或解密历史，不截图、不后台监听，也不发送消息。真实微信版本的兼容性仍需单独授权实测；系统辅助功能权限由你自行决定是否授予。

05 / 常见问题

保留现场，按实际错误处理。

更新检查失败或签名不匹配？

先检查网络与错误提示。不要跳过签名验证或改用来历不明的文件；可从本页官方 Release 下载对应版本并核对摘要。校验失败不代表更新已经安装。

更新后仍像旧版本，或启动没有完成？

确认打开的是刚安装的应用，并等待运行环境准备完成。预配失败可能继续使用旧运行时；保留启动错误和数据备份，向维护者反馈应用版本及错误信息，不要先删除整个数据目录。

微信提示未识别、标题不符或缺少权限？

保持微信主窗口中的目标聊天可见，核对完整标题与系统辅助功能权限。布局不支持时停止本次读取，不应扩大到其他聊天或抓取全部历史来绕过。再次尝试仍需一次新的批准。

Linux 提示密钥服务不可用？

本地执行记录使用系统 Secret Service。根据系统提示解锁可用的密钥服务；没有可用服务时会明确报错，不能把失败当成已保存。

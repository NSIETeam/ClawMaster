DEVELOPMENT GUIDE · 0.2.0-RELEASE

使用ClawMaster
进行开发

把需求、源码、终端和网页预览放在一个工作台。从已有项目的小问题开始，先理解，再修改，用代码差异和实际操作确认结果。

适用于 ClawMaster WatchDog 0.2.0 · 面向已有项目的开发者 · 练习使用本地测试数据

01 / 准备项目与开发环境

选择一个能在本机复现的小问题。

练习场景：网页的必填字段输入空格也能提交。目标是拒绝空白，保留正常提交和既有长度规则。也可换成你项目里的明确缺陷，并替换模板。

  1. 准备项目的 Git 工作副本，保存已有修改，记录当前分支与提交。另建开发分支处理本次问题；没有 Git 的项目先保存可恢复副本。
  2. 按项目 README 准备依赖、编译器、测试数据和开发服务。ClawMaster 自带的运行环境用于启动应用，不能代替项目所需的 Python、Java、数据库或其他工具。
  3. 复现一次，记下页面、输入、实际与预期结果。记录已有测试错误，区分新旧问题。

尚未配置模型时，先按 WatchDog 教程的安装与模型准备完成连接。使用本地测试环境，避免用真实客户提交表单。

02 / 打开正确的工作区

让任务对应到项目目录。

  1. 点击工作区标题栏的添加工作区，在应用内目录浏览器中选择项目根目录，也可直接输入路径，点击打开。
  2. 使用该工作区的新建会话入口进入新会话。发送任务前确认当前工作区，避免在 WatchDog 自动分配的空目录里寻找已有项目。
  3. 需要查看文件或运行命令时，打开文档编辑器和终端。文档在右侧、终端在底部；它们使用关联会话的工作空间。
应该看到

文件树包含项目说明和源码目录。让 AI 报告当前目录，核对后再继续。

03 / 先读源码

先要依据与方案，再要代码。

把复现步骤和读取范围一起交给 AI。文件名、函数名和测试入口须有源码依据；资料不足时先补充。

只读要求也要与实际权限配合。新会话默认只读文件访问并询问审批；已有用户保存的设置优先。源码中被用于任务的内容可能发给你配置的模型服务，按项目要求选择可使用的资料与模型。

04 / 确认修改范围

把“修好了”写成可以检查的结果。

确认根因后，约定修改文件、空白规则和测试范围。新增依赖、改数据库或扩展其他模块前，先确认原因与影响。

出现写入或命令审批时，核对目录、目标文件和操作影响；符合本次范围再批准。被拒绝的操作需要调整方案，不能通过放宽全部权限继续。

05 / 编辑与测试

让修改和检查对应起来。

AI 修改后，在文档编辑器打开相关文件核对。需要人工接手时先保存编辑，避免你和 AI 同时修改同一文件；切换会话或退出前也先保存。

  1. 在终端确认当前目录，使用项目实际声明的测试命令，先跑受影响的功能测试。
  2. 根据改动补充项目要求的类型检查、格式检查或构建。页面、接口和数据迁移各有不同检查。
  3. 读取实际输出：是否执行了目标用例，有没有跳过、缺失凭据或服务未启动。失败时保留错误并定位原因。
本例的验收标准

合法名称可提交；空字符串与三个空格被拒绝；最短合法输入、长度上限及超长输入符合原规则。若只测到前端，需要明确服务端写入是否仍未验证。

06 / 浏览器核验

亲手走一遍用户会做的操作。

按项目说明启动开发服务，在网页浏览器输入实际输出的本地地址。确认使用最新代码，再按原步骤操作。

  1. 提交空字符串和三个空格，检查提示是否清楚，以及测试记录是否确实没有增加。
  2. 提交合法名称，检查成功反馈与实际保存值；再验证已约定的长度边界。
  3. 刷新后复查结果。涉及布局时检查窄窗口和键盘操作，确认提示没有遮挡按钮。

命令成功只能说明该项检查通过，不能代表全站验收。页面受嵌入、登录或环境限制无法核验时，改用系统浏览器检查并记录结果；这一步不会自动证明其他页面也正常。

07 / 复核差异与提交

把可复核的修改留在项目里。

在项目目录查看 git status --short、git diff --stat 和 git diff。这些只读命令适用于已安装 Git 的 macOS、Windows 和 Linux；本教程通过终端操作 Git。

  1. 对照开工前记录，区分本次修改、你原有的工作以及新增文件。确认没有顺手改动无关模块。
  2. 逐项核对实现、测试与文档，不把密钥、日志或无关构建产物加入提交。
  3. 需要 AI 提交时，在原会话明确授权“仅将本次已审阅文件提交到当前开发分支”，核对暂存内容后完成本地提交。

本地提交、推送和发布是不同操作。推送或发布前另行明确仓库、分支、环境与范围，遵循审核流程。收尾记录提交号、检查结果和未验证项。

08 / 失败与恢复

从已有状态继续，避免重复改动。

模型或应用中断了，怎么继续？

重新打开项目的原会话，先检查已保存文件、Git 差异和仍运行的进程，再描述中断位置。未保存的编辑不能靠会话记录恢复；ClawMaster 不会自动替你回滚整个项目。

终端找不到命令或服务起不来？

核对当前目录、项目要求的工具版本和依赖安装结果。把完整错误交给 AI 分析；权限、缺失工具和代码错误分别处理，不把无法执行的测试记为通过。

修改后出现新问题？

先保存当前差异，用原复现步骤缩小范围，再决定修复或撤销本次特定改动。已有他人或自己的未提交修改需单独保留，避免整目录覆盖或强制重置。

下一次，从一个更清楚的问题开始。

保留复现、修改和验证记录，让下次开发更容易接手。

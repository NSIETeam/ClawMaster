# 成事五步法（Musk · The Algorithm）

马斯克在火箭与产线上反复验证的五步，**顺序本身就是结论**：绝大多数失败源于顺序颠倒——在没删除的东西上做优化，在没简化的流程上做自动化，在没质疑的需求上做加速。

五步：
1. **质疑每项需求**——每条需求都来自某个人。给它写上提出者的名字。聪明人提的需求最危险，因为没人敢质疑。
2. **删除**——删掉部件或流程。如果之后加回来的东西超过删掉的 10%，说明删得不够狠。
3. **简化并优化**——最常见的错误是优化一个根本不该存在的东西。必须先删，再简。
4. **加速**——缩短周期时间。只有前三步做完才允许加速，否则你只是在更快地做错事。
5. **自动化**——最后一步。过早自动化会以极快速度、极高一致性放大错误流程（特斯拉 Model 3 产线的教训：自动化→拆掉→重来）。

## 何时使用

用户带来一个流程、计划、组织安排、产品功能集，想降本增效、提速、或者"总觉得哪里笨但说不上来哪里笨"。

## 工作流

### Step 1：清单化

让用户把对象拆成可见的单元：流程则列每个环节（谁做、耗时、为什么存在），产品则列每个功能/部件（谁提的、为谁服务），计划则列每个动作。用户列不全时，按业务常识补全并标注"(补)"。

### Step 2：逐步过堂

对每个单元依次执行：

**质疑**：这条需求为什么存在？给提出者命名。它服务真实产出，还是服务汇报、免责、或某位领导的偏好？
**删除**：直接删掉会发生什么？最坏后果有多大、多可能？删掉的候选写进删除清单。
**简化**：删剩下的，能不能用更少的步骤/字段/审批/页数达成同样效果？
**加速**：哪个环节是串行其实可以并行的？哪个环节是瓶颈（约束理论：全链速度由最慢一环决定，优化非瓶颈环节是假功夫）？
**自动化**：哪些环节自动化时机成熟（量大、规则稳定、已简化）？哪些是在自动化一个还没简化的烂流程（危险信号）？

### Step 3：危险信号检查

明确回答三个问题：
1. 有没有在**优化不该存在的东西**？（环节删掉后问题消失 = 该删）
2. 有没有在**自动化没简化的流程**？
3. 有没有在**加速没删除的环节**？

任一为真，这是一票否决项，放在报告最显眼处。

### Step 4：输出

```markdown
# 五步法审视：<对象>

## 危险信号（顺序颠倒检查，一票否决项置顶）
## 删除清单（每条：删什么 → 谁提的 → 为什么可以删 → 加回来超过10%怎么办）
## 简化清单
## 瓶颈与加速机会
## 自动化时机表（现在自动化 / 再等等 / 永远别自动化）
## 执行顺序（严格按 1→5 排，写明哪些动作必须先于哪些动作）
```

## 硬性规则

- 删除建议必须附"最坏后果"推演，不许无脑喊删。
- 每条需求要落到提出者/来源；用户说不出来源的，本身就是危险信号（无主需求）。
- 不替用户拍板删除；给出删除后的验证方式（小范围试运行、回滚条件）。

# 企业容量诊断

[English](README.md) | 中文

## 摘要

[诊断程序](enterprise.perf.ts)在独立 Node 进程中通过编译适配器测量生产 SQLite 启动和已注册的 HTTP 处理器。它创建合成数据库，记录全部样本，并删除临时产物和数据。程序不打开用户工作区。这是维护者参考，不是已安装桌面应用的性能测试，也不是必需的 CI 时间门槛。

<a id="run"></a>
## 运行

按锁文件安装根目录和前端依赖，然后在自己管理的其他构建及基准均空闲时，从仓库根目录运行：

```sh
node --import tsx/esm frontends/dsh/benchmarks/enterprise.perf.ts --output /tmp/clawmaster-capacity.json
```

默认每个集合分别包含 100、1,000、10,000 条记录，每档采集五个独立进程样本。`--tiers 100,1000` 和 `--samples 3` 可选择较短的诊断。每档数量必须在 1 到 10,000 之间，样本数必须在 2 到 20 之间。每个工作进程限时两分钟。TypeScript 加载器仅用于编排；被测进程清除 `NODE_OPTIONS` 后，在普通 Node 下运行编译后的 JavaScript。

<a id="measurements"></a>
## 测量

每档包含等量客户、库存项和单行草稿订单，审计条目数量为每类记录数的五倍。二十家公司和十个供应商提供重复搜索词。准备数据使用生产命令回执 API。每个样本都在独立临时目录中接收已经关闭的种子数据库副本。

| 操作 | 计时终点 |
| --- | --- |
| `open` | 存储初始化和校验；不包含模块导入和进程启动 |
| `overview` | HTTP 版本、计数与已配置上限 |
| `list`、`search` | 首个客户分页，最多 50 条记录，使用默认 256 KiB 字节预算 |
| `auditTail` | 通过校验版本的修订区间读取最后 50 条审计记录 |
| `saveReceipt` | 修改一个现有客户并序列化命令回执 |
| `backup` | 工作进程导出并流式下载为 Blob |
| `prepareBackup` | 上传原始 Blob、工作进程校验及小型复核响应 |
| `restore` | 工作进程事务、授权检查与持久回执序列化 |

报告包含全部耗时样本、最近秩 p50/p95、响应字节、各操作前后 RSS、堆占用及Host 与子进程各自的峰值 RSS，以及两者峰值相加的保守上界。每项操作前执行 GC。HTTP 测量包含请求体、处理器、序列化和客户端解码；备份下载保留为 Blob，不包含已认证的 DSH 传输层及网络。测试程序在准备与恢复期间保留下载的 Blob，因此内存也包含放在被测进程中的模拟浏览器存储。即时回调记录 Host 事件循环的最大调度间隔，包含最终同步执行段。这衡量 Node 调度，不是浏览器输入延迟。

<a id="interpretation"></a>
## 解释

报告记录检出提交、工作树是否有修改、适配器与备份工作进程摘要、Node 版本、架构和机器内存。编译适配器使用检出目录安装的外部包。报告应与确切的检出版本和锁文件一同保留。不清除文件系统缓存；新进程不等于冷磁盘。五个样本的 p95 就是最慢样本，不能视为总体分位数估计。

列表和回执大小可以有界，但启动校验、备份和恢复的成本仍随历史增长。调查回归时需比较相同数据规模和操作终点。不要通过删除校验或历史来改善数值。验收限制和排除范围见[测量决策](../../../.agents/notes/implemented/testing/2026-09-16-clawmaster-enterprise-capacity.zh.md)。

<a id="measured-workload"></a>
## 实测负载

[93d05b1 候选版本报告](2026-09-17-candidate-93d05b.json)记录 macOS arm64、6 个逻辑 CPU、8 GiB 内存、Node 24.20.0 环境下每档三次的结果。报告标识了干净的源码提交，并记录两个编译产物的哈希。每个 p95 都是三次观察中的最大值，不代表总体分位估计。下表单位为毫秒，格式为 p50/p95。本次完成了 100 条和 1,000 条记录档；10,000 条记录档的种子生成超过现有工作进程的 120 秒期限，因此三档验收仍未完成，也不能据此确定支持容量档位。

| 操作 | 100 条记录 / 500 条审计 | 1,000 条记录 / 5,000 条审计 | 响应字节数，100 / 1,000 |
| --- | --- | --- | --- |
| 打开及完整校验 | 81.1 / 137.8 | 437.7 / 727.2 | — |
| 概览 | 61.0 / 84.9 | 80.4 / 124.1 | 169 / 174 |
| 首屏分页 | 12.3 / 14.5 | 13.2 / 27.7 | 9,016 / 9,018 |
| 搜索 | 4.2 / 7.7 | 11.8 / 15.8 | 995 / 9,052 |
| 审计尾页 | 10.0 / 17.6 | 18.6 / 29.2 | 20,559 / 20,562 |
| 保存回执 | 10.3 / 21.9 | 18.5 / 29.4 | 160 / 162 |
| 下载备份 | 401.2 / 422.2 | 950.1 / 3,358.8 | 405,127 / 4,091,334 |
| 上传及校验 | 264.2 / 299.2 | 851.4 / 2,329.6 | 267 / 272 |
| 确认恢复 | 495.0 / 498.0 | 4,362.6 / 7,566.9 | 144 / 145 |

在这两档中，保存回执的响应大小基本不变。导出文件约为 0.4 MB 和 4.1 MB。所有被测操作中 Host 与子进程峰值 RSS 的最大和为 181.7 MiB 和 214.1 MiB；这是分别观测的进程峰值之和这一保守上界，并非同时采样值。这次本地测量只报告诊断成本，不构成验收预算或用户容量承诺。它不包含安装、已认证 DSH 传输、浏览器输入与绘制、冷文件系统缓存或外部应用。[全快照基线](2026-09-16-paged-enterprise.json)和[工作进程备份报告](2026-09-16-worker-backups.json)仍是较早且源码树有修改时的历史观测，不能作为本候选版本的证据。

本提交单独复测 10,000 条记录档时，也在现有两分钟工作进程期限内超时。夹具种子使用生产回执命令生成，且不计入操作计时；因此超时表示诊断准备受限，不是某项操作延迟的测量值。不要通过提高超时把未完成档位改称容量结论。

### 历史报告

以下 2026-09-16 数据来自所链接报告中记录的较早脏工作树，仅为保留历史比较；它不能替代 93d05b1 候选版本未完成的三档验收。

| 操作 | 100 条记录 / 500 条审计 | 1,000 条记录 / 5,000 条审计 | 10,000 条记录 / 50,000 条审计 |
| --- | --- | --- | --- |
| 打开及完整校验 | 18.2 / 18.9 | 96.7 / 99.7 | 842.9 / 1041.0 |
| 概览 | 23.0 / 24.8 | 24.8 / 25.4 | 25.7 / 26.3 |
| 首屏分页 | 3.3 / 3.5 | 3.7 / 3.8 | 4.2 / 5.3 |
| 搜索 | 1.1 / 1.4 | 5.5 / 6.2 | 16.6 / 17.1 |
| 审计尾页 | 3.5 / 3.6 | 3.8 / 4.4 | 4.1 / 5.8 |
| 保存回执 | 1.9 / 2.2 | 2.4 / 2.6 | 2.5 / 3.1 |
| 下载备份 | 89.8 / 92.8 | 254.0 / 274.0 | 1847.5 / 1967.9 |
| 上传及校验 | 83.0 / 83.7 | 182.6 / 215.2 | 1066.6 / 1069.4 |
| 确认恢复 | 88.5 / 94.1 | 214.2 / 277.8 | 1523.9 / 1568.8 |

恢复回执为 144 / 145 / 146 字节，准备响应为 267 / 272 / 277 字节。导出文件约为 0.4 / 4.1 / 41.4 MB。仅 Host 的峰值 RSS 为 89.8 / 109.5 / 228.7 MiB；各操作的子进程峰值单独记录。Host 与子进程峰值的最大和为 168.5 / 233.2 / 551.0 MiB，这是保守上界，不是同时采样得到的峰值。最大档恢复期间 Host 最长调度间隔为 7.0 毫秒，导出为 13.0 毫秒。全快照基线达到 771.1 MiB 和 5.54 秒恢复停顿。进程启动会增加小文件延迟；准备与确认是分别测量的操作。可配置的文件/堆上限可能拒绝更大导入，原生分配不受 V8 堆上限限制。32 MiB 堆失败被隔离在私有执行器中；回归证明 Host 与数据库仍可使用。这些结果不构成已安装桌面验收。

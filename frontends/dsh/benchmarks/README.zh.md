# 企业容量诊断

[English](README.md) | 中文

## 摘要

[诊断程序](enterprise.perf.ts)在独立 Node 进程中通过编译适配器测量生产 SQLite 存储。它创建合成数据库，记录全部样本，并删除临时产物和数据。程序不打开用户工作区。这是维护者参考，不是已安装桌面应用的性能测试，也不是必需的 CI 时间门槛。

## 目录

- [运行](#run)

<a id="run"></a>
## 运行

按锁文件安装根目录和前端依赖，然后在自己管理的其他构建及基准均空闲时，从仓库根目录运行：

```sh
node --import tsx/esm frontends/dsh/benchmarks/enterprise.perf.ts --output /tmp/clawmaster-capacity.json
```

默认每个集合分别包含 100、1,000、10,000 条记录，每档采集五个独立进程样本。`--tiers 100,1000` 和 `--samples 3` 可选择较短的诊断。每档数量必须在 1 到 10,000 之间，样本数必须在 2 到 20 之间。每个工作进程限时两分钟。TypeScript 加载器仅用于编排；被测进程清除 `NODE_OPTIONS` 后，在普通 Node 下运行编译后的 JavaScript。

<a id="measurements"></a>
## 测量

每档包含等量客户、库存项和单行草稿订单，审计条目数量为每类记录数的五倍。二十家公司和十个供应商提供重复搜索词。准备数据使用生产命令回执 API。每个样本都在独立临时目录中接收已经关闭的种子数据库副本。

| 操作 | 计时终点 |
| --- | --- |
| `open` | 存储初始化和校验；不包含模块导入和进程启动 |
| `list`、`search` | 首个客户分页，最多 50 条记录、64 KiB 字节预算 |
| `auditTail` | 使用偏移查询读取最后 50 条审计记录 |
| `saveReceipt` | 修改一个现有客户并序列化命令回执 |
| `snapshot` | 完整校验后的状态及审计历史序列化为 JSON |
| `backup` | 可恢复备份序列化为 JSON |
| `restore` | 原子恢复及返回快照序列化为 JSON |

报告包含每个耗时样本、最近秩 p50/p95、响应字节数、每项操作前后的 RSS、操作后的堆使用量和进程峰值 RSS。每项操作前执行 GC。观察内存时结果对象和 JSON 文本仍然可达；恢复期间保留备份。即时回调记录操作期间最大的事件循环调度间隔，包括最后一段同步阻塞。它测量 Node 调度，不代表浏览器输入延迟。

<a id="interpretation"></a>
## 解释

报告记录检出提交、工作树是否有修改、工作进程摘要、Node 版本、架构和机器内存。编译适配器使用检出目录安装的外部包。报告应与确切的检出版本和锁文件一同保留。不清除文件系统缓存；新进程不等于冷磁盘。五个样本的 p95 就是最慢样本，不能视为总体分位数估计。

列表和回执大小可以有界，但全量快照、启动校验、备份和恢复的成本仍随历史增长。调查回归时需比较相同数据规模和操作终点。不要通过删除校验或历史来改善数值。验收限制和排除范围见[测量决策](../../../.agents/notes/implemented/testing/2026-09-16-clawmaster-enterprise-capacity.zh.md)。
